# Database Tour Pro - SQL editor for tables you administer

A live query and a named table view should share one window on a database you administer. Extra export tabs wait for their own title.

## Session Card

| Slice | What you do in Database Tour Pro | What remains |
|-------|----------------------------------|--------------|
| Arrival | Open Database Tour Pro on a database you administer and name the SQL window | A titled SQL desk |
| Focus | Keep one query and one Database Tour Pro table view in front | A short result set |
| Check | Read the last statement before you change rows you own | A confirmed query |
| Handoff | Leave the Database Tour Pro SQL editor on the named database | A note for the next visit |

## How Database Tour Pro Sits

Database Tour Pro does not replace the engine you already run. It sits beside that server as a named SQL editor and table view for Database Tour Pro own databases. Everyday work stays on schemas you administer.

## Traffic Light

| Signal | On the Database Tour Pro desk | What you do |
|--------|-------------------------------|-------------|
| Green | Named database, one live query | Continue the same statement |
| Amber | Two databases mixed in one window | Split the set before a large change |
| Red | No title, exports everywhere | Stop and name the SQL desk first |
| Clear | Handoff written, results few | Close Database Tour Pro and leave the desk |

## Open Order

1. Open the last Database Tour Pro session on a database you administer, not a new empty editor.
2. Read the last query and the table view in front of you.
3. Finish one visible statement inside Database Tour Pro.
4. Write what changed on your own tables, then close with fewer loose result tabs than you found.
5. If the window feels crowded, drop anything that belongs to a different Database Tour Pro job.

## After a Week

A week in Database Tour Pro is not more connection tabs. It is the same named SQL editor, a shorter query list, and a note that still makes sense on Monday. Leave Database Tour Pro with a quieter data desk than the one you opened.

## Sign-off

- [ ] The Database Tour Pro workspace name is short enough to scan
- [ ] Only live queries on databases you administer are open
- [ ] A second person can read the last statement
- [ ] The last Database Tour Pro session still opens after a restart
- [ ] Finished result tabs are off the live set
- [ ] The Database Tour Pro table view still matches the query

## Field Note

Database Tour Pro is easier to trust when the SQL editor stays smaller than the export folder it came from. Name the session, keep Database Tour Pro own databases in view, finish one statement, and write what changed.
